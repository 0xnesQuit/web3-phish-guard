Guard3 drill

A harmless page that behaves like a wallet drainer. Nothing here can move funds: every request targets a dead address on whatever chain your wallet is on, and you reject it in the wallet anyway. The point is to see which requests the extension holds before the wallet shows them.

0. Status

Expected: no hold. Connecting is normal. The extension only notes a connect that happens without a click.

1. Always held, on every site

Expected: the red extension dialog appears for each of these, whatever the page's score. On Ethereum mainnet the token is USDC, so the dialog also shows its symbol and your balance, and (for transactions) a simulation block with what the call would really do; the spender stays a dead-looking address and you reject anyway. On other chains the token reads simply find no contract. "Reject" → the page sees error code 4001 and the wallet never shows the request. "Allow" → the wallet's own prompt appears; reject it there.

2. Held only when the page looks risky

Expected on a clean page: straight to the wallet. Open this page with #w3pg-drill=45 (warn) or #w3pg-drill=75 in the URL and reload: the extension pretends the page scored that much (localhost only), and these are held too. The multicall and batch must be held at any score because they hide an unlimited approve. "Transfer 1 USDC" (transfer(DEAD, 1e6)) is the one to use with #w3pg-drill=45 on mainnet to see the simulation's "Leaves your wallet" line (it needs at least 1 USDC in the wallet, otherwise the simulation says the call would revert).
