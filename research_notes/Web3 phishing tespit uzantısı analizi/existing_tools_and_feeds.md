# Existing Web3 / crypto phishing detection tools, blocklists, databases, APIs and libraries (state as of 17 Oct 2026)

Scope note: inventory of reusable data sources and tools for a Chrome/Brave extension that warns on crypto phishing sites (fake mint / airdrop / token pages). All claims cite a source; numbers are as shown on the cited page on the fetch date (17 Oct 2026). Where I could not verify something it is listed under Gaps.

## KQ1. MetaMask eth-phishing-detect: blocklist / allowlist / fuzzylist mechanics, review process, merge speed, phishing-warning page

### Takeaway
`MetaMask/eth-phishing-detect` is the de-facto open Web3 domain blocklist (200k+ domains, single `src/config.json` with `blacklist`, `whitelist`, `fuzzylist`, `tolerance: 1`), but the matching code has moved to `@metamask/phishing-controller` in MetaMask/core, and production MetaMask does not read the GitHub file; it pulls a hosted stalelist (30-day refresh) plus hotlist diffs every 5 minutes from `phishing-detection.api.cx.metamask.io`, plus a hashed C2-domain blocklist and a remote URL scanner. The repo is now fed almost entirely by an automated `security-alliance-bot` (SEAL) sync, with MetaMask staff reviewing contributions from ChainPatrol, SEAL and ~100 community members; MetaMask claims warnings reach users "within minutes" of listing.

### Cited Findings

Repo stats on fetch: 1.3k stars, 1.1k forks, 23 open issues, 7 open PRs, 257,036 commits. **Hosted endpoints actually used by MetaMask (from PhishingController.ts)**
- Base `https://phishing-detection.api.cx.metamask.io`; stalelist at `/v1/stalelist`; hotlist diffs at `/v2/diffsSince/{lastUpdated}`. Refresh constants: stalelist 30 days (2,592,000 s), hotlist 5 minutes (300 s), C2 domain blocklist 5 minutes (300 s). `ListNames` contains only `MetaMask`; `ListKeys` only `eth_phishing_detect_config` (no PhishFort list in current code) — [PhishingController.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingController.ts)
- C2 domain blocklist: `https://client-side-detection.api.cx.metamask.io/v1/request-blocklist` (returns `recentlyAdded` / `recentlyRemoved`, request timestamp rounded to the minute) — [PhishingController.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingController.ts)
- dApp scanning: `https://dapp-scanning.api.cx.metamask.io` with `v2/scan` (single URL, 8 s timeout, GET, `x-request-source` header, result cached by hostname, returns hostname + recommended action) and `bulk-scan` (max 250 URLs/call, batches of 50, 15 s timeout, URLs > 2,048 chars rejected). Security alerts base `https://security-alerts.api.cx.metamask.io` (`/token/scan-bulk`, `/address/evm/scan`, `/address/evm/approvals`) — [PhishingController.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingController.ts)
- I fetched `https://phishing-detection.api.cx.metamask.io/v1/stalelist` without any auth header and received JSON: `{ data: { tolerance: 1, version: 2, lastUpdated: 1792124340 (~15 Oct 2026 06:05 UTC), allowlist: ~57 domains, fuzzylist: 8 domains, blocklist: very large } }` (~2.5 MB). Keys `name`, `c2DomainBlocklist`, `blocklistPaths` were not visible in the first 100 kB — [stalelist endpoint](https://phishing-detection.api.cx.metamask.io/v1/stalelist)
- Allowlist "bypass": `bypass(origin)` persists the hostname into state `whitelist` (or only the path into `whitelistPaths` if the block was path-based); `testOrigin` / `isBlockedRequest` return not-blocked for whitelisted hostnames — [PhishingController.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingController.ts)

**Exact detection algorithm (PhishingDetector.ts)**
- Order of checks in `check()`: (1) IPFS CID regex over the whole URL — regex `Qm[1-9A-HJ-NP-Za-km-z]{44,}|b[A-Za-z2-7]{58,}|B[A-Z2-7]{58,}|z[1-9A-HJ-NP-Za-km-z]{48,}|F[0-9A-F]{50,}` — a CID that appears as a single-label blocklist entry returns `Blocklist`; (2) parse hostname with `new URL()`, strip trailing dot, split into labels; (3) per-config `blocklistPaths` trie prefix match → `Blocklist`; (4) allowlist across all configs → `Allowlist`, `result:false` (overrides hostname blocklist but NOT path blocklist); (5) per-config blocklist → `Blocklist`; if miss and `tolerance > 0`, fuzzy check; (6) default `{result:false, type:All}` — [PhishingDetector.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingDetector.ts)
- Fuzzy check: hostname → `domainPartsToFuzzyForm`, strip leading `www.`, compute `fastest-levenshtein` `distance` against each fuzzylist target in the same form; match when `distance <= tolerance` → type `Fuzzy`, `result:true`. With `tolerance: 1` in config this means only 1 edit from one of the 8 brands — [PhishingDetector.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingDetector.ts); [config.json](https://raw.githubusercontent.com/MetaMask/eth-phishing-detect/main/src/config.json)
- Blocklist/allowlist entries match "the listed domain or subdomain thereof" (label-array suffix matching via `matchPartsAgainstList`) — [PhishingDetector.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingDetector.ts)
- `isMaliciousC2Domain()`: allowlist check, then SHA-256 of lowercased hostname and of up to 5 parent domains, looked up in a `Set` of hashes (`c2DomainBlocklist`) → type `C2DomainBlocklist`. Result types: `All, Allowlist, Blocklist, Fuzzy, C2DomainBlocklist`; legacy mode maps to `Whitelist`/`Blacklist` — [PhishingDetector.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingDetector.ts)
- A fork's doc claims the default tolerance is 3 but config sets 2 — contradicted by the live config and stalelist which both show `tolerance: 1` — [fork doc](https://github.com/marius-bardan/eth-phishing-detect/blob/master/doc/lists-ref.md) vs [config.json](https://raw.githubusercontent.com/MetaMask/eth-phishing-detect/main/src/config.json)

**Contribution, review and false-positive policy**
- Contribution is via CLI (`yarn add:blocklist <domain>`, `yarn add:allowlist`, `yarn remove:*`) or library `addDomains(config,"blocklist",[...])`, not hand-editing. CI safeguards: `test/resources` contains "popular lists" (one host per line; refreshed with `yarn update:lists`, needs a CoinMarketCap Pro key); to block a domain on those lists you must add a bypass in `test/test-lists.ts`. Audit: `git log -S "example.com" -- src/config.json`. Blocking policy: sites that "Impersonate other known and established sites" or use their interfaces to collect signing keys; "other grounds for blocking" exist. Lookup/dispute tool: https://app.chainpatrol.io/search — [README](https://github.com/MetaMask/eth-phishing-detect)
- CONTRIBUTING.md: "Maintainers are responsible for reviewing contributions"; fork → branch → PR; GitHub Issues for bug reports; links to `doc/fp-policy.md` — [CONTRIBUTING.md](https://raw.githubusercontent.com/MetaMask/eth-phishing-detect/main/CONTRIBUTING.md)
- fp-policy.md (applies to contributors with write/review access): 1st false positive → MetaMask holds a call to review the contributor's pipeline; 2nd → another call, MetaMask leads required changes; 3rd → "their write/review access is revoked" and all contributions reviewed; "If we do not make contact with you after 3 business days" review permissions are revoked directly. No appeal process described — [fp-policy.md](https://raw.githubusercontent.com/MetaMask/eth-phishing-detect/main/doc/fp-policy.md)
- MetaMask (15 Oct 2024): "Dedicated MetaMask staff review contributions from ChainPatrol, the Security Alliance (SEAL), and over 100 community members"; ChainPatrol is MetaMask's phishing-detection provider using image recognition, LLM analysis and malicious-code detection; ChainPatrol blocked >29,000 threats targeting Consensys/MetaMask/Linea Jan–Oct 2024; "users see a warning within minutes of detection"; phishing sites "taken down within 15 minutes" (body says measured from blocklist addition, chart caption says from detection — internally inconsistent); false-positive disputes "addressed within minutes" via app.chainpatrol.io/search; MetaMask staff monitor eth-phishing-detect issues — [MetaMask news](https://metamask.io/news/metamask-chainpatrol-protect-users-with-phishing-warnings)
- Merge activity observed 17 Oct 2026: the 15 most recent merged PRs (#303332–#303348) are all titled "Synchronize repository" / "blocklist addition", all by `security-alliance-bot`, all merged the same day — i.e. the list is now fed by an automated SEAL sync in many small batches per day. Open/creation timestamps were not visible so exact PR-to-merge latency could not be measured — [merged PRs](https://github.com/MetaMask/eth-phishing-detect/pulls?q=is%3Apr+is%3Amerged)
- SEAL (Security Alliance) impact claim: ">150,000 phishing domains blocked" attributed to SEAL 911 — [GuideStar profile](https://www.guidestar.org/Profile/92-3456081); SEAL released a "Verifiable Phishing Reporter" using "TLS attestations" in Oct 2025 — [The Block via TradingView](https://tr.tradingview.com/news/the_block:6ebff56fd094b:0-crypto-crime-research-group-seal-org-unveils-new-way-to-report-potential-phishing-sites)

**MetaMask phishing-warning page mechanism**
- Repo https://github.com/MetaMask/phishing-warning: "A page to warn users about a suspected phishing site"; published to npm mainly so it can be hosted locally for e2e tests; "isn't meant to be used as a library" — [MetaMask/phishing-warning](https://github.com/MetaMask/phishing-warning)
- `src/index.ts`: reads `href` from the URL **hash** (`new URLSearchParams(hash.slice(1)).get('href')`), derives hostname (punycode `toUnicode`), origin. "Continue" (`#unsafe-continue`) first rejects `javascript:`, `data:`, `vbscript:` hrefs, then sends JSON-RPC `safelistPhishingDomain` with params `[suspectHref]` over a `WindowPostMessageStream` (name `metamask-phishing-warning-page`, target `metamask-contentscript`) multiplexed via `ObjectMultiplex` on stream `metamask-phishing-safelist`, then sets `window.location.href` to the suspect URL; "Back to safety" sends `backToSafetyPhishingWarning`. The safelist is kept on the extension side (no localStorage in the page). "Report a new issue" links to `https://github.com/MetaMask/eth-phishing-detect/issues/new`. Startup hash `#extensionStartup`; a service worker is registered at `./service-worker.js` — [phishing-warning src/index.ts](https://raw.githubusercontent.com/MetaMask/phishing-warning/main/src/index.ts)
- MetaMask user-facing behaviour: a "Deceptive site ahead" warning is shown before a wallet connects to a flagged site; MetaMask runs its own URL scanning — [MetaMask support](https://support.metamask.io/stay-safe/safety-in-web3/deceptive-site-ahead-when-trying-to-connect-to-a-site)

### Inferences
- For a third-party extension, the cheapest high-quality source is the hosted stalelist (`/v1/stalelist`, no auth observed, includes allowlist + fuzzylist + tolerance) refreshed rarely, plus `/v2/diffsSince/{ts}` every few minutes — this mirrors what MetaMask itself does and avoids downloading the 3 MB GitHub file repeatedly. However these are MetaMask-operated endpoints with no published third-party SLA or ToS found; treat as "works today, may break".
- The fuzzylist is deliberately tiny (8 brands, tolerance 1) to avoid false positives; it will NOT catch e.g. `opensea-mint.xyz` — those must be in the explicit blocklist. Building a wider brand/keyword heuristic is where a new extension can add value, but MetaMask's fp-policy shows how seriously false positives are treated.
- Latency from first report to a MetaMask user warning depends on the pipeline: SEAL/ChainPatrol automated adds → bot PR → hotlist diff (5 min poll). The vendor's "within minutes" claim is plausible but unverified independently.
- The DBAD license is permissive but non-standard; legal review for a commercial product is advisable.

### Gaps
- Exact PR open→merge latency for eth-phishing-detect could not be measured (PR list shows merge dates only).
- `utils.js` (`matchPartsAgainstList`, `applyDiffs`, `domainPartsToFuzzyForm`) was not read; subdomain semantics are inferred from code comments.
- No published terms of use / rate limits for `phishing-detection.api.cx.metamask.io` found.
- The production hosting URL of the phishing-warning page (historically `metamask.github.io/phishing-warning/`) is not in the source file I read; not verified.

## KQ2. ScamSniffer: scam-database repo, update cadence, drainer signatures, API, reporting, extension

### Takeaway
ScamSniffer publishes a GPL-3.0 open database (`blacklist/domains.json` plain string array, `blacklist/address.json`) that is refreshed daily but released with a 7-day delay versus its paid real-time feed; the real-time edge API (`lookup-api.scamsniffer.io`) costs from $999/month. No drainer JS signatures are published in the open repo. The Chrome extension (40k users, v0.0.60, last updated Feb 2025) does site/address blocking, signature checks, simulation and X/Telegram alerts, with a freemium model.

### Cited Findings
- Repo https://github.com/scamsniffer/scam-database: contains `blacklist/domains.json` ("regularly updated list of known phishing domains targeting crypto users") and `blacklist/address.json`; license GPL-3.0; "Our data is refreshed every 24 hours"; "Open-source data is released with a 7-day delay"; contribute via PR or issue; contact fun@scamsniffer.io; paid real-time blocklist API "$999 per month"; stats 1,451 commits, 254 issues, 37 PRs, 267 stars; listed users: Phantom, Rabby, ByBit, Binance, OpenSea, Chainalysis, BlowFish, TokenPocket, Forta — [scamsniffer/scam-database](https://github.com/scamsniffer/scam-database)
- Raw URL (verified fetch): https://raw.githubusercontent.com/scamsniffer/scam-database/main/blacklist/domains.json — a single JSON array of bare hostname strings, ~9.1 MB of text; first entries e.g. `votes-okxpolls-89.pages.dev, governance-meridianfi.xyz, okxrewards-claimtokenhold.netlify.app, sendusdt-usd.vercel.app, 26-reallocate-flare.pages.dev, securitynote-x.com`; entries mimic OKX, Robinhood, Pendle, Hyperliquid, Xaman with "claim/airdrop/wallet-connect/verify" patterns — [domains.json](https://raw.githubusercontent.com/scamsniffer/scam-database/main/blacklist/domains.json)
- Address list raw URL (inferred from blob path, not fetched): https://raw.githubusercontent.com/scamsniffer/scam-database/main/blacklist/address.json — [repo](https://github.com/scamsniffer/scam-database)
- Website: API endpoint `https://lookup-api.scamsniffer.io/site/check?url=...` with `x-api-key` header, returns `BLOCKED` / `PASSED`; "One edge API, served from Cloudflare's network"; offers domain/URL checks, single/batch address checks, blocklist exports. Tiers: Open source $0 (daily-updated domain blacklist, "free for commercial use", on GitHub); Standard from $999/month by query volume (real-time domain+URL blocklist, malicious address blocklist, REST lookup API); Enterprise custom (bulk feed, data licensing, drainer attribution, threat intel, SLA). Scale: "258K+ domains and malicious addresses", "47M URLs scanned", "705K scams identified"; "updated continuously"; entries "verified through automated checks and human review". Coverage: phishing sites, wallet drainers, scammer addresses, seed phishing — [scamsniffer.io](https://scamsniffer.io/)
- Chrome extension "Scam Sniffer" (id `mnkbccinkbalkmmnmbcicdobcmgggmfc`): 40,000 users, version 0.0.60, last updated 16 Feb 2025, 4.4/5 (25 ratings). Features: real-time malicious website detection via blocklist + "Web3 Safe Browsing"; signature security checks and transaction simulation; NFT listing/offer verification; approval monitoring; X (Twitter) phishing alerts and Telegram fake-bot alerts; frontend-compromise protection; fake app/game/browser malware detection; chains EVM, Solana, Sui, Ripple, BTC, TON, TRON. Premium on by default with a 0.25% fee on selected DEX trades; Free plan "with limited detections" — [Chrome Web Store](https://chromewebstore.google.com/detail/scam-sniffer/mnkbccinkbalkmmnmbcicdobcmgggmfc)
- ScamSniffer 2024 report figures (secondary summary): ~$494M lost to wallet drainers across ~332,000 addresses; Permit signatures in 56.7% of drainer thefts; main signature types Permit, setOwner, Transfer, increaseAllowance — [DeFiHackLabs summary](https://defihacklabs.substack.com/p/scam-sniffer-2024-web3-phishing-attacks)

### Inferences
- The free repo is usable client-side (plain string array, GPL-3.0 — note GPL may constrain a closed-source extension that bundles it; fetching at runtime avoids linking issues) but is 7 days stale by design, so it is a "long tail" source, not a first-response source.
- 9 MB raw JSON is too big to fetch repeatedly in an extension; diff locally or hash it.
- No open drainer-signature feed exists from ScamSniffer; drainer attribution is Enterprise-only.

### Gaps
- Entry counts for domains.json / address.json not computed (file truncated in fetch).
- No public community-reporting flow documented beyond GitHub issue/PR and email; the extension's in-app report feature not verified.
- Free-tier API rate limits for the lookup API not published.

## KQ3. Commercial / wallet-security products: Blockaid, Wallet Guard, Pocket Universe, Fire, Revoke.cash, Harpie, Web3 Antivirus, Kerberus, De.Fi Shield, Trugard, Forta

### Takeaway
The standalone consumer-extension market consolidated hard in 2024–2026: Wallet Guard (Consensys) sunset 31 Mar 2025, Harpie shut down 27 Mar 2025, Fire (2024) and Pocket Universe (Aug 2025) were absorbed by Kerberus Sentinel3, Blowfish was absorbed by Phantom (Nov 2024), and the Revoke.cash open-source extension repo was archived Mar 2026 (a new extension continues). Blockaid is the dominant B2B API (site scan `POST /v0/site/scan`) but docs and pricing are gated. Web3 Antivirus and Kerberus Sentinel3 remain active closed-source extensions; Forta pivoted to on-chain Firewall/Scam Detector; nothing current was found for De.Fi Shield or Trugard.

### Cited Findings
- **Blockaid**: dApp-scanning product claims "1.6 million malicious dApps blocked monthly" and "75 million domains scanned monthly", method = internet-wide crawling + new-domain-registration monitoring + sandboxed interaction simulation; detects "phishing pages, wallet drainers, and lookalike sites" — [blockaid.io dapp scanning](https://blockaid.io/platform/dapp-scanning); docs at https://docs.blockaid.io redirect to a login (`docs-login.blockaid.io`) — [docs.blockaid.io](https://docs.blockaid.io/); third-party API catalog lists `POST /v0/site/scan` (body: `url` + optional `metadata`) and `POST /v0/site/report` — [apis.io](https://apis.io/apis/blockaid/blockaid-site-api/); pricing not public (secondary) — [komo.ai](https://komo.ai/directory/blockaid); Portal proxies Blockaid URL scan returning `is_malicious` — [Portal docs](https://docs.portalhq.io/api-reference/blockaid/scan-a-url); Blockaid blog argues drainers are detectable by "distinct patterns in their API usage" — [Blockaid blog](https://www.blockaid.io/blog/wallet-drainers-vitalik-metamask); MetaMask integrated Blockaid security alerts Oct 2023 — [Consensys](https://consensys.io/blog/metamask-adds-privacy-preserving-security-alerts)

- **Phantom blocklist**: community list on GitHub (`phantom-labs/blocklist`, PRs append to `blocklist.yaml`, URL without protocol, explain reason in PR); maintainers say the list "is not meant for client-side apps" because its size causes performance problems when bundled; Phantom redirects to a Blocklist Page on hit; blocklist had >800 malicious NFT mint addresses — [Phantom docs (search snippet)](https://docs.phantom.app/developer-powertools/blocklist); [ecosyste.ms](https://awesome.ecosyste.ms/projects/github.com%2Fphantom%2Fblocklist). Note: the live docs page now at docs.phantom.com describes domain warnings ("new domain warning… usually clears after a few days") but no longer the repo — [docs.phantom.com](https://docs.phantom.com/developer-powertools/blocklist)
- **polkadot-js/phishing**: curated list for Polkadot/Substrate; `all.json` (sites) and `address.json`; served at https://polkadot.js.org/phishing/all.json and on IPFS; used by polkadot{.js} extension/apps, Talisman, Nova, Fearless, SubWallet; JS lib caches ~45 min — [GitHub](https://github.com/polkadot-js/phishing); [polkadot.js.org/phishing](https://polkadot.js.org/phishing/)
- **PhishFort**: supplied Brave's wallet phishing list since Sept 2020 (see KQ5) and historically a second list in MetaMask; current MetaMask code has no PhishFort list — [PhishingController.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingController.ts)

### Inferences
- The only vendor APIs a hobby/indie extension can realistically call for free are GoPlus `phishing_site` (also returns NFT contract risk — directly relevant to fake-mint detection) and ChainPatrol's "free API" (terms unverified). Blockaid and ScamSniffer real-time are enterprise-priced.
- Consolidation means a new extension competes mainly with Kerberus Sentinel3, Web3 Antivirus, ScamSniffer and wallet-built-in protection (MetaMask/Phantom/Rabby), not with Wallet Guard/Pocket Universe/Fire/Harpie.

### Gaps
- No reliable 2025–2026 information found on De.Fi Shield or Trugard (searches returned nothing); status unknown.
- Blockaid API pricing, rate limits and SDK package name (`@blockaid/client`) could not be verified — docs are login-gated.
- ChainPatrol API endpoint paths, auth and quotas not verified (docs 404).
- GoPlus phishing API quotas/pricing not stated in docs page read.
- Fire extension's current status (still published or merged) not confirmed.

## KQ4. Generic phishing feeds: Google Safe Browsing, PhishTank, OpenPhish, URLhaus, Phishing.Database, CryptoScamDB, Chainabuse, Netcraft, Cloudflare Radar, PhishDestroy

### Takeaway
Generic feeds are mostly free but with key/registration friction (PhishTank app key, URLhaus Auth-Key, Safe Browsing non-commercial key) and are not crypto-specific; the standout crypto-aware open feed is PhishDestroy's DestroyList (222k+ domains, CC0/MIT, raw JSON on GitLab, keyless REST API with drainer-type classification). CryptoScamDB appears dormant.

### Cited Findings
- **Google Safe Browsing Lookup API v4**: needs an API key in the URL; up to 500 URLs/request; threat types e.g. `MALWARE`, `SOCIAL_ENGINEERING`; responses carry `cacheDuration` (e.g. 300 s) — [Lookup API docs](https://developers.google.com/safe-browsing/v4/lookup-api). "The Safe Browsing API is for non-commercial use only… If you need a solution for commercial purposes, please refer to Web Risk"; no cost; default quota, more on request; warners must add attribution and the "accuracy can't be guaranteed" notice; may not block a URL unless data was refreshed within the past 30 minutes — [Permitted Use](https://developers.google.com/safe-browsing/reference/Appropriate.Usage); [Usage limits](https://developers.google.com/safe-browsing/v4/usage-limits)
- Chrome mechanics: local hash-prefix lists refreshed ~every 30 min (server-set minimum wait), only matching prefixes sent to Google — [Google Security Blog 2022](https://security.googleblog.com/2022/08/how-hash-based-safe-browsing-works-in.html); March 2024: Standard protection moved to real-time server-side checks via Oblivious HTTP because local lists refreshed every 30–60 min missed short-lived sites — [9to5Google](https://9to5google.com/2024/03/14/chrome-standard-safe-browsing/)
- **PhishTank** (Cisco Talos): feeds `http://data.phishtank.com/data/online-valid.json` / `.csv` (+ `.gz`, `.bz2`); keyed form `http://data.phishtank.com/data/<app key>/online-valid.json.bz2`; "Without this key, you will be limited to a few downloads per day"; updated hourly; set User-Agent `phishtank/[username]`; terms = Cisco EULA — [PhishTank developer info](https://phishtank.org/developer_info.php); new-user registrations closed since 2020 (Wikipedia, citation issues) — [Wikipedia](https://en.wikipedia.org/wiki/PhishTank)
- **OpenPhish**: community feed `https://raw.githubusercontent.com/openphish/public_feed/refs/heads/main/feed.txt`, text, updated every 12 hours; Premium/Platinum every 5 min with CSV/JSON, brand, ASN, GeoIP, sector, SSL metadata; Terms of Use apply, commercial-use column marked "Limited" (mapping unclear) — [OpenPhish feeds](https://openphish.com/phishing_feeds.html)
- **URLhaus (abuse.ch)**: malware-distribution URLs only (not phishing); dumps (full/active/30-day CSV+JSON), RPZ, hosts file, Snort/Suricata, ClamAV regenerated every 5 min; downloads need an `Auth-Key` in the path, e.g. `https://urlhaus-api.abuse.ch/v2/files/exports/YOUR-AUTH-KEY-HERE/recent.csv`; free "under the fair use principles", commercial use may need a paid subscription — [URLhaus API](https://urlhaus.abuse.ch/api/)
- **Phishing.Database (mitchellkrogza / Phishing-Database org)**: MIT; 497,247 domains, 784,405 links captured, 59,223 active links (page version V.2026-10-02.17); raw mirrors `https://phish.co.za/latest/ALL-phishing-domains.lst`, `.../ALL-phishing-links.lst`, `.../phishing-domains-ACTIVE.txt`, `.../phishing-links-ACTIVE.txt` (+ `.tar.gz`); repo files `phishing-domains-NEW-today.txt`, `phishing-domains-NEW-last-hour.txt`, `phishing-links-ACTIVE-NOW.txt`; validated with PyFunceble; official VirusTotal data vendor; "updated regularly" (no interval); FP via GitHub issues and `falsepositives/temporary/` lists; no crypto-specific coverage mentioned; spare-time maintenance — [Phishing.Database](https://github.com/mitchellkrogza/Phishing.Database)
- **CryptoScamDB**: `CryptoScamDB/blacklist` = "A dataset of various malicious cryptocurrency-related URLs and Twitter profiles", 577 commits, 60 stars, 66 open issues, not marked archived, no license shown, no last-commit date visible; api.cryptoscamdb.org status not determinable — [CryptoScamDB/blacklist](https://github.com/CryptoScamDB/blacklist); a Kaggle derivative "Cryptocurrency Scam Dataset" exists — [baselight/Kaggle](https://baselight.app/u/kaggle/dataset/zongaobian_cryptocurrency_scam_dataset)
- **Chainabuse (TRM Labs)**: Public API v1.2 with Get Report (screen addresses/contracts/token IDs/URLs), Post Report (batch), Get Report by ID; 16 categories; reports carry confidence score and verification status; evidence/geolocation/contact only in Chainabuse Pro for pre-vetted partners; "Proprietary API", contact hello@chainabuse.com; auth/pricing/rate limits not stated — [Chainabuse API docs](https://docs.chainabuse.com/docs/welcome-to-chainabuse-api)
- **Netcraft Extension**: free anti-phishing extension for Chrome/Firefox/Edge/Opera, in-extension reporting, blocks web-miner sites; store listing v2.1.2 with last update Feb 2024 (third-party audit) — [Netcraft apps](https://www.netcraft.com/apps/browser/); [extensionauditor](https://extensionauditor.com/scan/netcraft-extension-bmejphbfclcpmpohkggcjeibfilpamia). No public feed; Netcraft Phishing API is a paid service (used by Nominet) — [ICANN/Nominet slides](https://74.schedule.icann.org/files/content=t_attachment,f_%221.%20Domain_Watch_Nominet_20220613.pdf%22/1.%20Domain_Watch_Nominet_20220613.pdf)
- **Cloudflare Radar URL Scanner**: API with bearer token, up to 100 URLs per submission, phishing classification in report metadata, `page.domStructHash` lets you search for other scans with the same HTML structure (useful for clone detection); public by default, "unlisted" available; not crypto-specific — [Cloudflare docs](https://developers.cloudflare.com/radar/investigate/url-scanner/); [Cloudflare blog](https://blog.cloudflare.com/radar-url-scanner-early-access)
- **PhishDestroy DestroyList**: 222,967 domains tracked, 27,310 takedowns, 78,688 abuse reports, 967 brands; categories phishing, crypto drainers, scam infrastructure; raw JSON `https://gitlab.com/phishdestroy/destroylist/-/raw/main/list.json` (5.73 MB), DNS-active `https://gitlab.com/phishdestroy/destroylist/-/raw/main/dns/active_domains.json` (3.73 MB), STIX `https://phishdestroy.io/feeds/stix.json` (147 MB, 2026-08-14), MISP manifest `https://phishdestroy.io/feeds/misp/manifest.json`, HuggingFace `phishdestroy/destroylist`; REST API `https://api.destroy.tools` with `/v1/check` (threat flag, severity, risk score, source), `/v1/intel` (target brand, drainer type, kit name, scam type, VirusTotal/Safe Browsing reputation, hosting, screenshots) and `/domain/{hostname}/`; "no API key required; documented limits apply"; "Updated Daily" header; license stated CC0 1.0 data / MIT code on the page but HuggingFace card says MIT and the Live page says CC-BY-4.0 (inconsistent — check per feed) — [PhishDestroy dataset](https://phishdestroy.io/dataset); GitLab repo: MIT, 3,782 commits, "automatically updated by the PhishDestroy system", tags include "drainer" — [GitLab destroylist](https://gitlab.com/phishdestroy/destroylist); notes Inferno Drainer stores config on BNB Chain so JS payload can change without redeploy — [PhishDestroy drainer anatomy](https://phishdestroy.io/crypto-drainer-anatomy)
- **curben/phishing-filter**: phishing URL blocklist in hosts/dnsmasq/RPZ/Suricata/uBlock formats, updated twice daily, built from OpenPhish + IPThreat — [phishing-filter README](https://git.nixnet.services/curben/phishing-filter/raw/commit/c5fd7f7d34198e882cbdbd51d6201186103d2c20/README.md)
- **PhishUnt.io**: keyless open API, 10 req/s/IP (Spanish doc page) — [phishunt.io](https://phishunt.io/es/api/)

### Inferences
- For client-side use: PhishDestroy `active_domains.json` (3.7 MB, hostnames only) and MetaMask stalelist are the only crypto-focused bulk lists that are both open-licensed and small enough to ship/refresh in an extension; Phishing.Database (500k domains) and ScamSniffer (9 MB) need server-side preprocessing or Bloom filters.
- Safe Browsing Lookup API cannot legally back a monetized extension (non-commercial clause) and it duplicates what Chrome/Brave already do.
- URLhaus is irrelevant for phishing pages (malware URLs only); OpenPhish/PhishTank have no crypto tagging in the free tier.

### Gaps
- PhishTank: could not verify from the official site whether new API-key registrations are currently open.
- CryptoScamDB: last-commit date, license and API status not determinable from the fetched page; treat as unmaintained until verified.
- PhishDestroy API rate limits ("documented limits") not read.
- Chainabuse API auth/pricing not published on the welcome page.

## KQ5. Open labeled datasets of crypto phishing domains / drainer code for heuristics or ML

### Takeaway
No peer-reviewed, domain-level crypto-phishing dataset exists; the practical options are the operational blocklists (eth-phishing-detect config.json with its git history, ScamSniffer domains.json, PhishDestroy list.json + per-domain intel with drainer/kit labels, Phantom blocklist.yaml, polkadot-js all.json) as positive labels and the eth-phishing-detect `test/resources` popular lists / allowlists as negatives. No open corpus of drainer JavaScript signatures (Inferno/Angel/etc.) was found.

### Cited Findings
- PhishDestroy positions its dataset for "researchers, browser vendors, ML training, and academic use" with CC0, JSON + HuggingFace; `/v1/intel` adds target brand, drainer type, kit name, scam type labels — [PhishDestroy dataset](https://phishdestroy.io/dataset)
- Kaggle "Cryptocurrency Scam Dataset" is built from CryptoScamDB (community, license unstated) — [baselight/Kaggle](https://baselight.app/u/kaggle/dataset/zongaobian_cryptocurrency_scam_dataset)
- LegitPhish: large-scale annotated URL phishing dataset (generic, not crypto) — [ScienceDirect](https://www.sciencedirect.com/science/article/pii/S2352340925006961); Brno University of Technology domain dataset (Data in Brief, 2026) with >1M domains labeled phishing/malware/benign, generic — [FIT VUT](https://www.fit.vut.cz/research/result/c194220/)
- SolPhishHunter / SolPhishDataset: 64 phishing accounts, 8,058 phishing transactions on Solana — addresses/transactions, not domains — [arXiv 2505.04094](https://arxiv.org/pdf/2505.04094)
- IEEE DataPort Ethereum phishing addresses listing shows "Files have not been uploaded" — [IEEE DataPort](https://ieee-dataport.org/comment/8975)
- open-malsec (HuggingFace) is a general malicious-security dataset README; crypto coverage not confirmed — [HuggingFace](https://huggingface.co/datasets/openmalx/open-malsec/blob/main/README.md)
- Drainer signatures: ChainPatrol has proprietary "wallet drainer kit rules" — [ChainPatrol changelog](https://chainpatrol.io/changelog/wallet-drainer-rules); Blockaid detects drainers by API-usage patterns (proprietary) — [Blockaid blog](https://www.blockaid.io/blog/wallet-drainers-vitalik-metamask); SEAL advisory on CVE-2025-55182 React exploitation injecting drainers into legitimate sites recommends checking for assets loaded from unknown hosts — [Cointelegraph](https://cointelegraph.com/news/react-vulnerability-wallet-drainer-attacks-crypto-websites)
- eth-phishing-detect ships negative-label resources: popular-domain lists in `test/resources` (CoinMarketCap-derived) used by CI to prevent false positives — [README](https://github.com/MetaMask/eth-phishing-detect)
- Cloudflare `page.domStructHash` enables clustering pages with identical DOM structure (useful for building clone-template features) — [Cloudflare docs](https://developers.cloudflare.com/radar/investigate/url-scanner/)

### Inferences
- A training/evaluation set can be assembled from: positives = union of eth-phishing-detect blacklist (with `git log -S` timestamps for "time of listing"), ScamSniffer domains.json, PhishDestroy list.json; negatives = eth-phishing-detect whitelist + stalelist allowlist + `test/resources` popular lists + Tranco-style top lists. Label noise exists (hosting-platform subdomains such as `*.pages.dev`, `*.vercel.app`).
- Drainer-JS detection would have to be built from scratch (e.g. heuristics on `eth_sign`/Permit/`setApprovalForAll` call patterns, config fetched from BNB chain), since no open signature corpus exists.

### Gaps
- No academic dataset specifically of crypto-phishing *domains* found.
- No open repository of drainer kit JavaScript samples or YARA-style rules found (only commercial rules).
- Licenses of CryptoScamDB and Kaggle derivative unclear.

## KQ6. What Brave and Chrome already apply by default (to avoid duplication)

### Takeaway
Both browsers run Google Safe Browsing (generic phishing/malware, Chrome Standard mode now with real-time hash checks; Brave proxies the same lists and does not enable Enhanced mode). Brave additionally warns about "Crypto Wallets" list domains (PhishFort feed plus industry lists incl. the Ethereum Phishing Detector) but only in the context of its built-in wallet. Neither browser shows a crypto-specific warning for a fresh drainer domain before Safe Browsing/MetaMask lists catch it, which is the gap a dedicated extension can fill.

### Cited Findings
- Brave: "Brave uses Google Safe Browsing, which is enabled by default on all platforms"; covers websites, downloads, extensions; "URLs are never sent to the Google-operated server"; desktop requests go through a Brave-operated proxy; "the bulk of these checks are done locally using lists downloaded from the Safe Browsing server" — [Brave support: Safe Browsing in Brave](https://support.brave.app/hc/articles/15222663599629-Safe-Browsing-in-Brave)
- Claim that Brave does not enable Enhanced Protection (real-time lookup) — [ctrl.blog](https://o.ctrl.blog/entry/fraud-protection-alternate-browsers.html) (unverified secondary)
- Brave Wallet phishing list: Sept 2020 integration of PhishFort "open-source anti-phishing tools… detects crypto scams and immediately warns our users of any suspicious domains" — [Decrypt](https://decrypt.co/41239/brave-browser-now-protects-you-crypto-phishing-scams?amp=1); [PhishFort blog](https://phishfort.com/resources/blog-posts/rolling-out-phishing-protection-to-braves-crypto-wallet-users). Community thread shows the Brave warning text: domain is on a "Crypto Wallets" warning list "compiled from other industry lists, including the Ethereum Phishing Detector", user can continue at own risk, list described as voluntary and possibly incomplete; one user reports the flag only appears with Brave's crypto wallet enabled — [Brave community](https://community.brave.com/t/our-project-website-is-getting-flagged-for-ethereum-phishing-detection-and-it-is-a-legit-site/271831)
- Chrome: local hash-prefix list ~30 min refresh (2022) — [Google Security Blog](https://security.googleblog.com/2022/08/how-hash-based-safe-browsing-works-in.html); Standard protection moved to real-time server-side hash-prefix checks via Oblivious HTTP (Mar 2024) — [9to5Google](https://9to5google.com/2024/03/14/chrome-standard-safe-browsing/)
- Safe Browsing threat types relevant: `SOCIAL_ENGINEERING` (phishing) and `MALWARE` — [Lookup API](https://developers.google.com/safe-browsing/v4/lookup-api)
- MetaMask (if installed) independently blocks via its own lists and shows "Deceptive site ahead" — [MetaMask support](https://support.metamask.io/stay-safe/safety-in-web3/deceptive-site-ahead-when-trying-to-connect-to-a-site); Phantom redirects to its blocklist page on hit — [Phantom docs snippet](https://docs.phantom.app/developer-powertools/blocklist)

### Inferences
- Do not re-implement Safe Browsing; assume Google covers mass-market phishing after some delay. The extension's value is (a) crypto-specific lists with minute-level latency (MetaMask hotlist diffs, PhishDestroy, ChainPatrol) applied at page-load regardless of which wallet is installed, (b) heuristics for brand-new domains (fake mint/airdrop/claim patterns, lookalike brands beyond MetaMask's 8-entry fuzzylist, free-hosting subdomains), and (c) warning before wallet connect/sign.
- On Brave, a user with Brave Wallet disabled (common for MetaMask users) gets no crypto-specific warning from the browser at all.

### Gaps
- No current official Brave documentation found describing whether the PhishFort/"Crypto Wallets" list is still maintained in 2026 or its refresh cadence; brave-core source not inspected.
- Chrome's current exact local-list refresh interval not confirmed from a 2025–2026 Google document (sources say 30 min vs 30–60 min).
