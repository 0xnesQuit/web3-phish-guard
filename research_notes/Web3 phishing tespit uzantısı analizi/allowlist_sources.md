# Building and maintaining a "known projects + official domains" brand allowlist for a Web3 phishing-detection extension (as of 2026-10-17)

Method note: findings marked "(direct API probe, 2026-10-17)" were obtained by calling the live endpoint from this session; everything else is from fetched docs/pages. Roughly 15 tool calls were used; several vendor doc pages (CoinGecko rate-limit page, Alchemy NFT FAQ, DappRadar docs, Magic Eden docs) were unreachable or uninformative and are listed under Gaps.

## KQ1. Token projects: CoinGecko, CoinMarketCap, DefiLlama, token lists, explorers, Chainlist — coverage of "homepage"/app/claim domains

### Takeaway
DefiLlama `/protocols` is the single best free, keyless, redistributable source: 8,749 protocols, 8,574 with a Twitter handle, 5,277 with a URL (662 of which are already `app.` subdomains), new listings appearing the same day. CoinGecko gives richer per-coin `links` (homepage, twitter, telegram, discord, github) but only one coin per call on a 10k-credit/month free plan with attribution and no-redistribution terms. None of these sources systematically enumerates claim/airdrop subdomains.

### Cited Findings
- DefiLlama `GET https://api.llama.fi/protocols` returns 8,749 protocols; top-level fields include `url`, `twitter`, `github` (as a list on some entries), `gecko_id`, `cmcId`, `listedAt`, `category`, `chains`, `audits`, `description`, `logo`. Counts: 5,277 have `url`, 8,574 have `twitter`, 1,599 have `github`, 2,432 have `gecko_id` (i.e. ~6,300 protocols are NOT on CoinGecko = tokenless/pre-token). 662 `url` values start with `https://app.` (i.e. DefiLlama sometimes records the app subdomain rather than the marketing site). The newest `listedAt` was 2026-10-17 00:52 UTC, i.e. listings land the same day — [api.llama.fi/protocols](https://api.llama.fi/protocols) (direct API probe, 2026-10-17)
- Example of a pre-token project present on DefiLlama: an entry named "Axis" with `url: https://axis.to`, `twitter: AxisFDN`, `listedAt` = 2026-08-16 (epoch 1787263751). Whether this is the same "Axis Robotics" the user has in mind is unverified — [api.llama.fi/protocols](https://api.llama.fi/protocols) (direct API probe, 2026-10-17)
- DefiLlama's API is free and needs no authentication for most endpoints; a developer guide cites roughly 500 requests per 5 minutes on the free tier — [DEV Community guide](https://dev.to/stablecoinstrategist/how-developers-can-leverage-defillama-for-real-time-defi-analytics-56be); the field list in that guide is truncated and does not mention `twitter`, which the direct probe confirmed exists.
- DefiLlama's "airdrops" dashboard is a list of DeFi protocols without tokens that might launch one later, showing category, TVL, money raised, and how long ago each protocol was listed — [DL News](https://www.dlnews.com/articles/llama-u/how-to-navigate-defillama/); a Spanish guide puts the count at over 3,500 tokenless protocols — [Datawallet](https://www.datawallet.com/es/cripto/defillama-explained). There is no dedicated airdrops API endpoint documented; the same data is derivable from `/protocols` by filtering entries with no `gecko_id`/`symbol` (inference, see below).
- CoinGecko pricing: Demo $0 / 10k call credits per month / 100 calls per minute / 1 API key, "Attribution required"; Basic $35/mo ($29 billed yearly) 100k credits 300/min; Analyst $129/mo 500k credits 500/min; Lite $499/mo 2M credits 500/min; Pro $999/mo 5M credits 1,000/min. The FAQ says you may not sell, rent, lease, sub-license, redistribute, or syndicate access to the API, and paid plans must display "Data provided by CoinGecko" with a hyperlink — [CoinGecko API pricing](https://www.coingecko.com/en/api/pricing)
- CoinGecko `GET /coins/{id}` `links` object (probed with `uniswap`): `homepage: ["https://uniswap.org/"]`, `whitepaper`, `blockchain_site[]` (explorer links on 8 chains), `official_forum_url[]`, `chat_url: ["https://discord.gg/FCfyBSbCU5"]`, `announcement_url`, `snapshot_url`, `twitter_screen_name: "Uniswap"`, `facebook_username`, `telegram_channel_identifier`, `subreddit_url`, `repos_url.github[]`. The call succeeded without an API key from this session — [api.coingecko.com/api/v3/coins/uniswap](https://api.coingecko.com/api/v3/coins/uniswap?localization=false&tickers=false&market_data=false&community_data=false&developer_data=false) (direct API probe, 2026-10-17). Note: `homepage` is the marketing root only; no `app.`/claim subdomain is listed for Uniswap.
- CoinGecko `GET /coins/list/new` (latest 200 newly listed coins with activation timestamp, refreshed every 30 s) is paid-only (Analyst, Lite, Pro, Enterprise) — [CoinGecko docs: coins/list/new](https://docs.coingecko.com/reference/coins-list-new.md)
- CoinMarketCap free tier: 50 requests/minute and 15,000 credits/month (vs CoinGecko Demo 100/min, 10,000/month), per a CoinMarketCap academy comparison read from pricing pages on 2026-09-21 — [CoinMarketCap Academy](https://coinmarketcap.com/academy/id/article/understanding-crypto-api-subscription-models-for-traders-in-2026)
- MetaMask's eth-phishing-detect refreshes its false-positive protection lists (`test/resources`, one host per line) with `yarn update:lists`, which requires a CoinMarketCap Pro API key — i.e. MetaMask itself uses CMC's token-website list as an allowlist/false-positive guard — [MetaMask/eth-phishing-detect README](https://raw.githubusercontent.com/MetaMask/eth-phishing-detect/main/README.md)
- Uniswap token list schema (`https://uniswap.org/tokenlist.schema.json`, JSON Schema draft-07) defines versioned token entries; the search found no `homepage` field — [uniswap.org tokenlist schema](https://uniswap.org/tokenlist.schema.json)
- Etherscan name tags/labels: the Export Address Tags endpoint (`module=nametag&action=exportaddresstags`) is a PRO endpoint limited to the Enterprise tier, throttled to 2 calls/s and 100 calls/day, returning a CSV download link that expires after 5 minutes; the Metadata CSV is available exclusively through the API Pro Plus plan — [Etherscan docs exportaddresstags](https://docs.etherscan.io/api-reference/endpoint/exportaddresstags-v2), [Etherscan Metadata CSV](https://docs.etherscan.io/metadata-api/api-endpoint/metadata-csv). Etherscan labels cover addresses, not website domains.
- GitHub REST `GET /orgs/{org}` returns `blog` (website), `twitter_username`, and `is_verified` (verified domain badge). Probe for `Uniswap`: `blog: https://uniswap.org`, `twitter_username: Uniswap`, `is_verified: true` — [api.github.com/orgs/Uniswap](https://api.github.com/orgs/Uniswap) (direct API probe, 2026-10-17)

### Inferences
- A free, legally clean base layer can be built entirely from DefiLlama `/protocols` (url + twitter + github + gecko_id/cmcId cross-keys) plus GitHub org `blog`/`is_verified`; CoinGecko should be used only to enrich (Discord/Telegram/GitHub links) within the 10k/month budget, which at 1 credit per `/coins/{id}` call is enough to refresh roughly 10k coins per month — adequate for a one-time seed plus incremental updates of new listings, but not for daily full refreshes of CoinGecko's full coin set.
- CoinGecko's redistribution clause means the extension should ship a derived allowlist (your own curated JSON), not a mirror of CoinGecko data; DefiLlama has no such documented restriction (license not stated on the page fetched — gap).
- "Homepage" fields are root marketing domains. Since 662 DefiLlama URLs are already `app.*`, the allowlist should normalise to the registrable domain (eTLD+1) and treat all subdomains of an allowlisted eTLD+1 as trusted, with an explicit exception list for user-content hosts (vercel.app, github.io, pages.dev, etc.).
- Tokenless protocols on DefiLlama (no `gecko_id`) are the best structured feed for "pre-token / upcoming airdrop" projects that have TVL.

### Gaps
- CoinGecko's official rate-limit/credits documentation page (docs.coingecko.com/reference/common-errors-rate-limit) returned 404; limits above come from the pricing page and a CMC comparison, not an official CoinGecko doc about enforcement.
- DefiLlama's data license and exact official rate limit were not found on a primary page.
- Jupiter token API v2 fields (`website`, `isVerified`, organic score) and pricing: the docs page redirected (developers.jup.ag) and was not fetched.
- Chainlist (chainid.network) exposes chain RPC metadata, not project domains; not researched further.
- Completeness of CoinGecko `homepage` for claim subdomains across many coins: only one coin was probed.

## KQ2. NFT collections: OpenSea, Reservoir, Magic Eden, SimpleHash, Alchemy, NFTScan, Metaplex; can on-chain metadata be trusted?

### Takeaway
As of October 2026 the NFT-metadata-API landscape has thinned: SimpleHash shut down 2025-03-27 and Reservoir's NFT API was sunset 2025-10-15. OpenSea API v2 `GET /api/v2/collections/{slug}` (API key required) is the main remaining source of `project_url`, `twitter_username`, `discord_url`, `telegram_url`, plus `safelist_status` whose values are `not_requested` / `requested` / `approved` / `verified` / `disabled_top_trending`; only `verified` implies OpenSea reviewed the account. Alchemy (30M CU/month free) mirrors OpenSea collection metadata. On-chain `external_url` is set by whoever deployed the contract and is not independently verified.

### Cited Findings
- SimpleHash's API shut down on March 27, 2025 (acquired by Phantom); Alchemy published migration guides and offered 3 months of credits — [Alchemy migration guide](https://alchemy.com/blog/migrating-from-simplehash-to-alchemy), [Alchemy docs: SimpleHash migration](https://docs.alchemy.com/reference/simplehash-migration-overview)
- Reservoir announced on 2025-04-24 that Reservoir NFT, its API and associated services would be discontinued on 2025-10-15; new account creation was disabled; the codebase was made public for self-hosting; Alchemy and Sequence were named as migration partners; the team pivoted to Relay — [cryptonews.net](https://cryptonews.net/news/nft/30856993/), [MEXC news](https://www.mexc.com/news/572834). `GET https://api.reservoir.tools/collections/v7` returned no HTTP response (curl status 000) from this session — (direct API probe, 2026-10-17)
- OpenSea `GET /api/v2/collections/{slug}` response: required `collection`, `contracts[]{address,chain}`, `safelist_status`, `name`, `opensea_url`, `editors[]`, `is_disabled`, `is_nsfw`, `total_supply`; optional nullable `project_url`, `wiki_url`, `discord_url`, `telegram_url`, `twitter_username`, `instagram_username`, `description`, `category`, `owner`. Every request requires `x-api-key`. The spec does not list rate limits or the `safelist_status` values — [OpenSea API reference: Get Collection](https://docs.opensea.io/reference/get_collection). An unauthenticated probe of `/api/v2/collections/pudgypenguins` returned HTTP 200 from this session (direct API probe, 2026-10-17) — this contradicts the "API key required" statement; treat as possibly rate-limited/unofficial.
- `SafelistStatus` enum in opensea-js: `not_requested` (brand-new collections that haven't asked to be safelisted), `requested`, `approved` (approved on the site, can appear in search results), `verified`, `disabled_top_trending` — [ProjectOpenSea/opensea-js types.ts](https://raw.githubusercontent.com/ProjectOpenSea/opensea-js/main/src/types.ts)
- OpenSea verified badge: on an account it means OpenSea verified the account; on a collection it means the collection belongs to a verified account and has meaningful interest or sales; a badge is not an endorsement. Eligibility thresholds in OpenSea's own pages conflict (75 ETH volume on one help page, 25 ETH in an older snippet, 100 ETH in a 2023 blog post) — [OpenSea support 8867072](https://support.opensea.io/en/articles/8867072-what-is-a-verified-account-or-badged-collection), [OpenSea blog: verification update](https://opensea.io/blog/articles/an-update-on-verification-and-copymint-prevention)
- OpenSea doubled default /v2 rate limits in December 2023; a changelog entry notes Get Account and Get Collection fixed returning twitter and instagram usernames — [OpenSea changelog 12.12.2023](https://docs.opensea.io/changelog/12122023-updates); exact current numeric limits were not found.
- Alchemy pricing: Free tier 30M compute units per month and 300 CU/s (15 req/s); Pay-as-you-go $0.525 per 1M CU with 10,000 CU/s; NFT API is included as a Data API with no NFT-specific limits listed — [Alchemy pricing](https://www.alchemy.com/pricing). Alchemy's `getContractMetadata` v3 doc page (which exposes `openSeaMetadata.externalUrl/twitterUsername/discordUrl/safelistRequestStatus` per the user's premise) returned 404 in this session — gap.
- Alchemy posted an "NFT API endpoint deprecation notice" dated 2026-08-18 — [Alchemy changelog 2026/8/18](https://www.alchemy.com/docs/changelog/2026/8/18) (content not fetched; which endpoints are deprecated is a gap).
- Moralis documents "Verified Contracts & Collections" (a `verified_collection` flag sourced from marketplace verification) — [Moralis docs](https://docs.moralis.com/web3-data-api/evm/verified-contracts-collections)
- Magic Eden `GET https://api-mainnet.magiceden.dev/v2/collections/{symbol}` responded "You have exceeded the requests in 1 min limit!" on the very first unauthenticated call from this session, indicating a shared/tight anonymous limit — (direct API probe, 2026-10-17); the Magic Eden docs page returned 403 to the fetcher.
- Alchemy's NFT FAQ confirms the token-level metadata schema includes `external_url` (per-asset), distinct from collection-level OpenSea metadata — [Alchemy NFT API FAQ](https://www.alchemy.com/docs/reference/nft-api-faq)

### Inferences
- Because `external_url`/`contractURI` is written by the deployer, it should be treated as a *claim*, not a verification: a copy-mint scam contract can embed the real project's URL (harmless for the allowlist) or its own phishing URL (dangerous if ingested blindly). Only ingest on-chain `external_url` when the collection also carries OpenSea `safelist_status == "verified"` (or at least `approved` with volume) or when it matches a domain already linked from another independent signal (X bio, GitHub).
- With Reservoir and SimpleHash gone, the practical NFT sources in 2026 are OpenSea v2 (primary), Alchemy (mirror of OpenSea metadata, generous free tier), Moralis (verified flag), Magic Eden (Solana/Bitcoin, tight anonymous limits), and NFTScan (not researched).
- `safelist_status` semantics: `approved` means searchable on OpenSea, not identity-verified; an allowlist should require `verified` for automatic inclusion and route `approved` collections to manual or multi-signal review.

### Gaps
- Numeric OpenSea v2 rate limits per key were not found in the docs fetched.
- Alchemy `getContractMetadata` field list and CU cost per call: doc page 404.
- Magic Eden API auth/limits and collection fields (website/twitter/discord): docs blocked (403).
- NFTScan, Blur API, and Metaplex `external_url` handling on Solana were not researched due to the call budget.

## KQ3. Pre-token / upcoming-airdrop projects: where they appear early, and monitoring X bio links programmatically

### Takeaway
Pre-token projects surface earliest on DefiLlama (tokenless protocol listings, same-day), quest platforms (Galxe GraphQL API, token-gated), research databases (RootData, CryptoRank, DropsTab — all with free-but-tiny or paid-only tiers), and on X. X's API is now pay-per-use by default: a user lookup costs $0.01 per user returned and the user object exposes `url`, `entities.url.urls[].expanded_url`, `verified`, and `verified_type` (blue/government/business), so monitoring 10,000 project accounts daily costs on the order of $100/day (or less with the 24-hour dedup rule). Scraping X without the API remains contested legally.

### Cited Findings
- X API pricing (official, pay-per-usage): reads per resource returned — User $0.010, Post $0.005, Following/Followers $0.010; writes — Post create $0.015; webhook profile-update events $0.005. Requesting the same resource twice within a 24-hour UTC window is charged once. Pay-per-usage is capped at 3 million Post reads per monthly billing cycle; higher volume needs Enterprise. New users can earn $20 of free credits after adding a card and a first purchase — [docs.x.com pricing](https://docs.x.com/x-api/getting-started/pricing), [docs.x.com about X API](https://docs.x.com/x-api/getting-started/about-x-api)
- Legacy tiers per third-party trackers: Basic $200/month (15,000 reads, 50,000 writes), Pro $5,000/month (1M reads), Enterprise ~ $42,000/month; one source says legacy Basic subscribers were migrated to pay-per-use after 2026-06-01 and Pro after 2026-09-01 — [postproxy.dev](https://www.postproxy.dev/blog/x-api-pricing-2026/), [zernio.com](https://zernio.com/blog/twitter-api-pricing); sources conflict (one lists Basic at $100/10k reads) and the migration dates come from a single source — unverified.
- `GET /2/users/by/username/{username}` supports `user.fields` = `url` (the URL in the user's profile), `entities` (URLs in profile description), `verified`, `verified_type` (blue, government, business, none); `entities.url.urls[].expanded_url` is the fully resolved URL and is nullable — [docs.x.com user lookup by username](https://docs.x.com/x-api/users/user-lookup-by-username). Per-endpoint rate limits (15-minute windows) are not on that page — gap.
- X sued Bright Data in N.D. Cal. for scraping in violation of its terms; a judge dismissed X's claims (headline), mirroring the earlier dismissal of Meta's similar claims against Bright Data — [silicon.co.uk](https://silicon.co.uk/e-marketing/socialmedia/x-data-scraping-suit-563197/amp), [Mondaq](https://www.mondaq.co.uk/unitedstates/privacy-protection/1360650/scraping-the-bottom-of-the-barrel-x-corp-sues-bright-data-over-site-scraping). The 2026 docket status and the syndication endpoint (cdn.syndication.twimg.com) were not found — gap.
- Galxe exposes a public GraphQL endpoint (`https://graphigo.prd.galaxy.eco/query`) covering quests, spaces, credentials, leaderboards; access requires a server API token generated in the dashboard and sent in an `access-token` header — [Galxe docs: GraphQL API](https://docs.galxe.com/quest/graphql-api/overview), [Galxe auth](https://docs.galxe.com/quest/graphql-api/overview/authentication). Field-level schema for a space's website/Twitter was not confirmed.
- Layer3, Zealy, QuestN: no public API documentation surfaced in search; Layer3 uses Dune Sim for on-chain verification (vendor case study) — [Dune case study](https://community.dune.com/case-studies/layer3-x-dune)
- RootData API (third-party pricing summary): Basic free 1,000 credits/month (partial project/VC lookups), Plus $128/month 5,000 credits, Pro $328/month 30,000 credits, 60 requests/minute cap; a May 2026 report says the API has 21 interfaces and 200+ fields including a token-issuance calendar — [Quasa.io](https://quasa.io/video/rootdata-web3-asset-database-crypto-research-api-quasaio), [ChainCatcher](https://www.chaincatcher.com/en/article/2265413)
- DropsTab commercial API: Basic $19/month (6 endpoints, 100 req/min), Advanced $59/month (16 endpoints), Pro $299/month (23 endpoints, ~2M req/month), no free tier — [DropsTab commercial API](https://dropstab.com/uk/products/commercial-api)
- CryptoRank public API: free Sandbox 34 endpoints, 10,000 monthly credits, 400 calls/day, 10 calls/minute; drophunting (airdrop) data limited to overview on free; paid from $29/month, Advanced $149, Pro $475, Business $949 — [CryptoRank API pricing](https://cryptorank.io/public-api/pricing), [CryptoRank blog](https://cryptorank.io/insights/blog/best-free-crypto-api-in-2026)
- ENS text records: `url` and `com.twitter` are standard keys readable via viem `getEnsText`; only the name owner (or operator) can set resolver records, so the record reflects what the owner entered with no independent verification — [viem getEnsText](https://viem.sh/docs/ens/actions/getEnsText), [ENS integration guide](https://www.mintlify.com/ensdomains/ens-contracts/guides/integrating-ens)
- Farcaster via Neynar: `lookup user by username` returns profile bio and a `verified_accounts[]` array with `platform` (e.g. "x") and `username`, plus `verifications` (verified wallet addresses) — [Neynar: lookup user by username](https://docs.neynar.com/reference/lookup-user-by-username)
- GitHub org `is_verified` + `blog` + `twitter_username` (see KQ1 probe) — [api.github.com/orgs/Uniswap](https://api.github.com/orgs/Uniswap)
- Airdrop trackers (airdrops.io, Earndrop, CoinGecko "upcoming airdrops", Binance Alpha): no API documentation or data policy surfaced in search — gap.

### Inferences
- Cost model for X monitoring: with per-user dedup within 24 h, polling N project accounts once per day costs about N × $0.01/day (10k accounts ≈ $100/day ≈ $3k/month) — comparable to legacy Pro. Cheaper alternatives: poll only accounts tied to *new* DefiLlama/quest listings, and rely on webhook "profile update" events ($0.005 each) rather than polling for already-known accounts, if the webhook product covers third-party profiles (not verified).
- `verified_type == "business"` (gold check, paid "Verified Organizations") is a stronger identity signal than `blue`, which any subscriber gets; the allowlist pipeline should weight the bio link by `verified_type`.
- Quest platforms are where pre-token projects appear before DefiLlama (a project with no TVL, e.g. a robotics/DePIN brand, may run a Galxe/Zealy campaign first); Galxe's GraphQL is the only one with a documented API, so it is the practical early-signal feed.
- ENS/Farcaster/GitHub records are self-asserted but *cross-source*: a domain that appears in the X bio AND the GitHub org `blog` AND ENS `url` is very unlikely to be a phisher's, because the attacker controls at most one of those.

### Gaps
- X per-endpoint rate limits in the pay-per-use model, and whether profile-update webhooks can subscribe to arbitrary third-party accounts.
- Legal status in 2026 of scraping X profile pages (syndication endpoint) — no source.
- Layer3 / Zealy / QuestN / airdrops.io / Earndrop / Binance Alpha data access — nothing found.
- Linktree/Link3/Bento APIs not researched.

## KQ4. Crowdsourcing & curation: how MetaMask, ScamSniffer, ChainPatrol, Chainabuse, Rabby, Blockaid, DappRadar curate; reusable open allowlists

### Takeaway
Open *blocklists* are abundant (MetaMask config.json with 106,776 blocked domains, ScamSniffer scam-database GPL-3.0 with 7-day delay, ChainPatrol public list, PhishDestroy 170k+), but open *allowlists* are tiny: MetaMask's `whitelist` has only 58 entries and exists purely to suppress false positives, and Rabby/Blockaid/ChainPatrol keep their trust signals behind proprietary APIs. Rabby's open security-engine rules reveal the shape of a good trust model: scam feeds (Rabby, MetaMask, ScamSniffer) → danger; `communityCount == 0` or `popularLevel == very_low` → warning; Rabby-verified origin → safe; user whitelist/blacklist override.

### Cited Findings
- MetaMask `src/config.json` (main branch, 2026-10-17): `version 2`, `tolerance 1`, `fuzzylist` 8 entries, `whitelist` 58 entries (sample: pcswap.org, sophon.xyz, opensea.pro, monadbridge.com, opensea.foundation, opensea.com, reown.org, reown.com, walletconnect.foundation, walletconnect.network, magic.link, web3inbox.com, web3modal.com), `blacklist` 106,776 entries — [MetaMask/eth-phishing-detect config.json](https://raw.githubusercontent.com/MetaMask/eth-phishing-detect/main/src/config.json) (direct fetch, 2026-10-17)
- MetaMask contribution flow: use `yarn add:blocklist <domain>` / `yarn add:allowlist <domain>` (or `addDomains(config, "blocklist"|"allowlist", [...])`), never hand-edit; blocking policy targets sites that impersonate established sites or collect signing keys; domains present in `test/resources` (outside-source lists, refreshed with `yarn update:lists` using a CoinMarketCap Pro key) cannot be blocked without an explicit bypass in `test/test-lists.ts`; audit a domain's history with `git log -S "example.com" -- src/config.json`; the detector logic moved to MetaMask/core's phishing-controller — [MetaMask/eth-phishing-detect README](https://raw.githubusercontent.com/MetaMask/eth-phishing-detect/main/README.md). No formal allowlist acceptance criteria or review SLA are documented — gap.
- MetaMask support: site owners wrongly flagged should file an issue on the repo; MetaMask may whitelist the site depending on findings — [MetaMask support: Deceptive site ahead](https://support.metamask.io/stay-safe/safety-in-web3/deceptive-site-ahead-when-trying-to-connect-to-a-site)
- MetaMask PhishingController runtime data sources: stalelist `https://phishing-detection.api.cx.metamask.io/v1/stalelist` (refresh 30 days), hotlist diffs `/v2/diffsSince/{lastUpdated}` (refresh 5 min), C2 domain blocklist `https://client-side-detection.api.cx.metamask.io/v1/request-blocklist` (5 min), URL scan `https://dapp-scanning.api.cx.metamask.io/v2/scan?url=` (8 s timeout, 60 s cache, bulk-scan batches of 50 up to 250 URLs); allowlist precedence: `whitelistPaths` then `whitelist` hostname return "not blocked" before the detector runs; `bypass(origin)` adds to whitelist — [MetaMask/core PhishingController.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingController.ts)
- ScamSniffer `scam-database`: `blacklist/domains.json` and `blacklist/address.json`, refreshed every 24 h, open data released with a 7-day delay, real-time API $999/month, GPL-3.0 license, report via PR/issue or fun@scamsniffer.io; no whitelist in the repo — [scamsniffer/scam-database](https://github.com/scamsniffer/scam-database). ScamSniffer says every entry is verified by automated checks then human review when needed — [scamsniffer.io](https://scamsniffer.io/)
- ChainPatrol: confirmed threats go to a blocklist distributed to wallets, browsers, Google Safe Browsing and DNS resolvers such as Quad9; each report is reviewed by the team and AI-scored against the organization's thresholds; sources are human reports (web/Slack), automated detection across 50+ platforms (Google, YouTube, Twitter, app stores, Telegram, TikTok), and enrichment (DNS, HTTP, WHOIS). It maintains a public list of blocked threats any service can use; "Allow" exists only as a per-organization status, with no public allowlist submission process documented — [ChainPatrol: how it works](https://chainpatrol.com/docs/general/how-it-works)
- Chainabuse (TRM Labs) report API: `POST https://api.chainabuse.com/v0/reports/batch`, HTTP Basic auth with credentials from a Chainabuse profile; a domain report needs URL, scam category and description — [TRM docs: report parameters](https://docs.trmlabs.com/guides/chainabuse/post-reports-parameters), [TRM API: contribute reports](https://docs.trmlabs.com/api/chainabuse/reports/contribute-reports). It is report intake, not an allowlist.
- Rabby security engine connect rules (open source): 1001/1002/1003 `getOriginIsScam(url, "rabby"|"metamask"|"scamsniffer")` → danger; 1004 `origin.communityCount` (0–100) == 0 → warning; 1005 `origin.popularLevel` (very_low/low/medium/high) == very_low → warning; 1006 user originBlacklist → forbidden; 1007 user originWhitelist → safe; 1070 `apiService.isOriginVerified(url)` → safe. How communityCount/popularLevel/is_verified are computed is not in the repo — [RabbyHub/rabby-security-engine connect.ts](https://github.com/RabbyHub/rabby-security-engine/blob/main/src/rules/connect.ts)
- Blockaid dApp scanning: sandboxed simulation of a dApp's possible user actions; flagged if any simulated transaction is risky; discovery via new-domain-registration monitoring and web crawling — [Blockaid dApp scanning](https://blockaid.io/platform/dapp-scanning). No curated public allowlist documented — gap. In Uniswap's WalletConnect integration, Blockaid supplies "Malicious site"/"Safe site" and the separate "Verified" badge is Reown's domain-matches-app check — [Uniswap support](https://support.uniswap.org/hc/en-us/articles/37781087046029-Dapp-Protection-via-WalletConnect)
- Ronin wallet runs its own "Trusted Domain Levels" tiers based on developer reputation and also uses Blockaid — [Ronin support](https://support.roninchain.com/hc/en-us/articles/17574629214363)
- Consensys acquired Wallet Guard on 2024-07-03; team folded into MetaMask product safety; no open allowlist from Wallet Guard found — [Consensys blog](https://consensys.io/blog/consensys-acquires-wallet-guard-to-enhance-metamask-security)
- DappRadar API (2023 announcements): Explorer free tier 100 calls, On-demand $0.005/call, Trader $9.99/mo, Startup $199/mo, Advanced $499/mo, Enterprise custom; a dapps search endpoint can look up dapps by smart contract, name or exact website — [DappRadar blog](https://dappradar.com/blog/dappradar-api-crypto-traders-tier-announcement), [DappRadar whitepaper](https://whitepaper.dappradar.com/products/api). Both api-docs.dappradar.com and docs.dappradar.com failed DNS resolution from this session — current status unknown.
- Other open blocklists: PhishDestroy `destroylist` (170k+ crowd-sourced scam domains, DNS formats) and jarelllama/Scam-Blocklist (daily, newly created scam domains) — [dev.co destroylist](https://dev.co/security/open-source/destroylist), [phishing.army](https://phishing.army/)
- Trust Wallet has a "listing new dApps" developer process — [Trust developer docs](https://developer.trustwallet.com/developer/listing-new-dapps) (content not fetched).

### Inferences
- No wallet publishes a reusable, broad "official domains" allowlist; the closest open artefacts are MetaMask's 58-entry whitelist and its `test/resources` false-positive lists (derived from CoinMarketCap). An extension should therefore build its own allowlist and, conversely, contribute false positives upstream via eth-phishing-detect issues.
- Rabby's model (three scam feeds + community count + popularity + vendor verification + user overrides) is directly reproducible with open data: scam feeds = MetaMask config.json + ScamSniffer (7-day-delayed) + ChainPatrol public list; community count = number of independent sources listing the domain (DefiLlama, CoinGecko, GitHub, OpenSea, Galxe); popularity = Tranco/Cloudflare rank.
- MetaMask's 5-minute hotlist and 60-second URL-scan cache set the practical freshness benchmark for a blocklist; for an allowlist, daily refresh (matching DefiLlama/Tranco cadence) is adequate.

### Gaps
- MetaMask's internal review criteria for allowlist PRs, reviewer SLA and CODEOWNERS were not found.
- Rabby's data sources for `communityCount`/`popularLevel`/`is_verified` are in a closed backend (openapi.ts only wires `INITIAL_OPENAPI_URL`).
- ChainPatrol API endpoints, free-tier limits and allowlist submission: not documented on the page fetched.
- Argent, Ambire, Brave, Coinbase Wallet dapp lists: the search returned nothing relevant.
- Google Safe Browsing allow mechanisms: not researched.

## KQ5. Alternative strategy: deriving trust at runtime (verified-X link, user history age, Tranco/Cloudflare rank, domain age, OpenSea back-link) — feasibility and supporting APIs

### Takeaway
Every runtime signal proposed has a workable free or cheap API: Tranco (daily top-1M CSV, no login, per-domain rank history API), Cloudflare Radar (weekly top-1M bucket, token required), RDAP via rdap.org (10 req/10 s, free) for domain age, X API ($0.01 per user lookup) for bio links, and OpenSea `project_url` for NFT back-links. A phishing domain is almost never in Tranco's top 1M, is days old, and is linked from nothing; a brand-new legitimate `.xyz` is also absent from Tranco and young, so rank/age signals can only *clear* a domain, never condemn it — cross-source linkage must do the positive work.

### Cited Findings
- Tranco: list of one million domains averaged over 30 days across four providers (Cisco Umbrella, Majestic, CrUX, Cloudflare Radar), updated daily by 00:00 UTC, zipped CSV at `/top-1m.csv.zip` (also `-incl-subdomains`), permanent ID URLs, BigQuery tables, and a `/query` page/API for historical ranks of individual domains; provider licenses: Umbrella free, Majestic CC BY 3.0, CrUX CC BY-SA 4.0, Cloudflare Radar CC BY-NC 4.0; Tranco's own license not stated — [tranco-list.eu](https://tranco-list.eu/). Probe: `GET https://tranco-list.eu/api/ranks/domain/uniswap.org` returned daily ranks (12,651 on 2026-10-16) without a key — (direct API probe, 2026-10-17)
- Cloudflare Radar: ranking derived from 1.1.1.1 DNS queries; ordered top-100 plus unordered buckets including a 1,000,000-domain bucket covering the last seven days, updated weekly; bucket download needs an API token via `radar/datasets?datasetType=RANKING_BUCKET`; `radar/ranking/domain/{domain}` gives only a bucket for domains outside the top 100 — [Cloudflare Radar domain ranking datasets](https://developers.cloudflare.com/radar/investigate/domain-ranking-datasets/), [Cloudflare API: ranking domain](https://developers.cloudflare.com/api/resources/radar/subresources/ranking/subresources/domain/methods/get)
- RDAP: rdap.org is a bootstrap redirector (302 to the authoritative registry RDAP server), rate-limited by Cloudflare to 10 requests per 10 seconds (HTTP 429 beyond), donations raise limits; gTLD responses follow the ICANN gTLD RDAP profile/RFC 9083 (registration event dates are part of that profile but the page does not confirm per-TLD) — [about.rdap.org](https://about.rdap.org/)
- X user object fields `url`, `entities.url.urls[].expanded_url`, `verified`, `verified_type` at $0.01 per user read — [docs.x.com user lookup](https://docs.x.com/x-api/users/user-lookup-by-username), [docs.x.com pricing](https://docs.x.com/x-api/getting-started/pricing)
- OpenSea collection `project_url`, `twitter_username`, `safelist_status` (see KQ2) — [OpenSea Get Collection](https://docs.opensea.io/reference/get_collection)
- Blockaid finds new malicious sites by monitoring new domain registrations — [Blockaid dApp scanning](https://blockaid.io/platform/dapp-scanning) — which confirms domain age is a signal used by incumbents.
- MetaMask's own runtime approach: live URL scan endpoint with 60 s cache, hotlist diffs every 5 min — [MetaMask/core PhishingController.ts](https://raw.githubusercontent.com/MetaMask/core/main/packages/phishing-controller/src/PhishingController.ts)
- Rabby's runtime approach: `popularLevel` and `communityCount` warnings plus user whitelist — [rabby-security-engine connect.ts](https://github.com/RabbyHub/rabby-security-engine/blob/main/src/rules/connect.ts)

### Inferences
- Feasibility by signal: (a) Tranco membership: trivially feasible offline (ship a Bloom filter of the daily top-1M, ~1–2 MB) — but only ~12k rank for Uniswap shows that many legitimate crypto sites sit far down the list, so the threshold must be the full 1M, not top-100k. (b) Domain age via RDAP: feasible client-side but 10 req/10 s on rdap.org means the extension should query the registry RDAP server directly (bootstrap from IANA) or cache aggressively. (c) User-history age: purely local (`chrome.history`), no API cost, strong signal against first-visit phishing. (d) X bio-link match: feasible server-side only (API key + cost), so run it in the allowlist build pipeline, not in the extension. (e) OpenSea back-link: server-side, needs an API key.
- Signals (a)–(c) are *negative-risk-reducers* ("this is probably not phishing") and (d)–(e) are *positive-identity* signals; a brand-new legitimate project fails (a)–(c) and must be cleared by (d)–(e) plus the cross-source linkage in KQ6.

### Gaps
- Whether rdap.org or the .xyz/.io registry RDAP servers reliably return the `registration` event date — not verified by a probe.
- Cloudflare Radar free-tier token quota — not stated on the pages fetched.
- Tranco list license for redistribution inside an extension — not stated.

## KQ6. Detecting that a NEW legitimate project domain (brand-new .xyz) is legit: cross-signal consistency vs scam isolation

### Takeaway
A new legitimate domain is "well connected": the same eTLD+1 appears in the project's X bio (`verified_type` business/blue), in the GitHub org `blog` of a verified org, in DefiLlama `url` (same day as listing), in OpenSea `project_url` of a `verified` collection, and in ENS `url`/Farcaster profile — each record controlled by a different platform account. A phishing clone controls none of these except, at best, a freshly made X account; so the scoring rule "≥ 2 independent platform records point to this eTLD+1" separates them, and the open MetaMask/ScamSniffer/ChainPatrol blocklists plus fuzzy-match against the allowlist catch the imitators.

### Cited Findings
- DefiLlama lists new protocols the same day (`listedAt` max = 2026-10-17 00:52 UTC) with `url` and `twitter` — [api.llama.fi/protocols](https://api.llama.fi/protocols) (direct API probe, 2026-10-17)
- GitHub org API exposes `is_verified` (domain-verified org), `blog`, `twitter_username` — [api.github.com/orgs/Uniswap](https://api.github.com/orgs/Uniswap) (direct API probe)
- X user lookup exposes profile `url` and `verified_type` (blue/government/business) — [docs.x.com user lookup](https://docs.x.com/x-api/users/user-lookup-by-username)
- OpenSea `safelist_status == verified` implies the collection belongs to an OpenSea-verified account with meaningful interest or sales — [OpenSea support](https://support.opensea.io/en/articles/8867072-what-is-a-verified-account-or-badged-collection), [opensea-js SafelistStatus](https://raw.githubusercontent.com/ProjectOpenSea/opensea-js/main/src/types.ts)
- ENS `url`/`com.twitter` records are set only by the name owner — [ENS integration guide](https://www.mintlify.com/ensdomains/ens-contracts/guides/integrating-ens); Neynar returns Farcaster `verified_accounts` (platform "x" + username) linking a Farcaster identity to an X handle — [Neynar lookup user by username](https://docs.neynar.com/reference/lookup-user-by-username)
- MetaMask's detector uses a `fuzzylist` (8 entries) with `tolerance 1` (edit distance) to catch look-alikes of high-value brands, in addition to the 106,776-entry blacklist — [MetaMask config.json](https://raw.githubusercontent.com/MetaMask/eth-phishing-detect/main/src/config.json)
- Galxe spaces/quests are reachable via its GraphQL API (token required) — [Galxe docs](https://docs.galxe.com/quest/graphql-api/overview) — giving a pre-TVL signal for projects that have no DefiLlama entry yet.
- Blockaid's approach for unknown sites is behavioural (simulate the dapp's transactions) rather than identity-based — [Blockaid dApp scanning](https://blockaid.io/platform/dapp-scanning)

### Inferences
- Proposed scoring for a candidate domain D (eTLD+1): +2 if D is the `url` of a DefiLlama protocol; +2 if D is the `blog` of a GitHub org with `is_verified == true` (+1 if not verified); +2 if D is the bio URL of an X account with `verified_type == business`, +1 for `blue`; +2 if D is `project_url` of an OpenSea `verified` collection (+1 for `approved`); +1 for an ENS `url` record on a name older than 1 year; +1 for a Galxe space link; −∞ if D or any label is in MetaMask/ScamSniffer/ChainPatrol blocklists; and a *separate* look-alike check: if D is within edit distance 1–2 (or contains the brand token) of an allowlisted brand but D itself scores < 2, flag as impersonation. Threshold ≥ 3 → auto-allow; 1–2 → "unknown, show caution"; this is an inference from the sources, not a tested rule.
- The "isolation" test must also check *account age* of the linking X/GitHub accounts, since a scammer can create an X account, a GitHub org and a Galxe space pointing to the fake domain; X `created_at` and GitHub org `created_at` are both available in the respective APIs (GitHub confirmed by probe schema; X `created_at` is a standard `user.fields` value but was not re-verified here).
- For the "Axis Robotics"-style case (pre-token, no CoinGecko entry): the DefiLlama probe found an "Axis" entry with `axis.to` / @AxisFDN listed 2026-08-16, which illustrates that DefiLlama catches some pre-token brands; projects with no TVL at all will only be visible through X, GitHub, Galxe/Zealy and RootData/CryptoRank — so the pipeline's early-warning feed should be "new DefiLlama listings ∪ new Galxe spaces ∪ RootData/CryptoRank new-project feeds", each resolved to an X handle and then to the bio URL.
- Because a scam campaign for an upcoming airdrop typically precedes or coincides with the real claim site, the allowlist should also record the *announced* claim domain from the project's own X posts (Post reads at $0.005 each) once the handle is known; this is the only source that reveals `claim.<brand>.xyz` before users hit it.

### Gaps
- No empirical study was found quantifying how often legitimate new crypto domains are linked from ≥ 2 independent platforms within their first week; the scoring thresholds above are untested.
- Whether X `created_at` and account-age fields are included under the pay-per-use user read was not re-verified.
- Linktree/Link3/Bento, Binance Alpha, airdrops.io/Earndrop and Crunchbase were not researched (call budget), so their value as early signals is unknown.
